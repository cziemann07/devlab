## O que você vai aprender e construir

Ao término do núcleo desta unidade, sua dupla deverá ser capaz de **capturar dados**, **representar escolhas**, **validar quantidade** e **calcular um resumo que se atualiza sozinho**. A aplicação proposta é uma simulação de pedido: não há compra, pagamento, banco de dados ou envio para uma pizzaria real.

**Entregas observáveis:** formulário compreensível; nome reativo; tamanho associado ao preço; múltiplos sabores; quantidade de 1 a 10; total calculado; uma explicação oral ou escrita do funcionamento; dois registros de Git quando executado no laboratório.

### Como os conceitos da Unidade 01 reaparecem

## O cenário real que vamos problematizar

Imagine uma cantina que recebe pedidos em uma folha de papel. Uma pessoa muda a quantidade, mas o total anotado não é atualizado. Outra seleciona vários sabores, mas só o último aparece. A interface digital deve **ajudar a evitar incoerências**. Antes de programar, a turma negocia regras: quais campos são indispensáveis? Qual quantidade é aceitável? Quem deve decidir o preço?

### Regras de negócio desta versão didática

- **Cliente:** texto livre; antes de preencher, o resumo indica “Não informado”.
- **Tamanho:** pequena = R$ 25; média = R$ 35; grande = R$ 45. Os valores são uma tabela de exercício e podem ser modificados.
- **Sabores:** seleção múltipla (checkboxes). **A seleção de sabores não muda o valor** nesta versão.
- **Quantidade:** de **1 a 10**, sem permitir valores negativos nem zero.
- **Preço:** `preço unitário do tamanho × quantidade`; é recalculado automaticamente.
- **Finalização (extra):** confirma apenas uma simulação local; não há persistência nem checkout.

> **Pergunta de investigação:** se duas pizzas médias custam R$ 70 e duas grandes custam R$ 90, qual dado mudou entre esses dois pedidos? E qual permaneceu igual?

### Anatomia de um arquivo `.vue`

```vue
<script setup>
import { ref } from 'vue'
const cliente = ref('') // estado reativo
</script>

<template>
  <input v-model="cliente" />
  <p>Olá, {{ cliente || 'visitante' }}!</p>
</template>

<style>
p { color: #188958; }
</style>
```

**Linha a linha:** a importação permite usar a API de reatividade; `ref('')` representa um texto inicialmente vazio; `v-model` conecta o campo ao estado; `{{ ... }}` mostra a informação no template; CSS modifica a cor. No `<script setup>` acessamos o conteúdo do `ref` com `.value`; no template, o Vue já realiza o desempacotamento.


## Transferência: vamos testar um pedido de outra dupla

Em vez de o autor demonstrar que "funciona", peça a outra dupla que execute **uma bateria de testes** e registre o resultado.

| Caso de teste | Ação | Resultado esperado |
|---|---|---|
| Nome vazio | Apagar campo do cliente | Resumo mostra “Não informado” |
| Médio e quantidade 2 | Selecionar média e clicar `+` | Total: R$ 70,00 |
| Grande e quantidade 2 | Mudar só o tamanho | Total: R$ 90,00 |
| Sem sabores | Desmarcar todos | Aparece aviso de nenhum sabor |
| Vários sabores | Marcar Mussarela e Calabresa | Ambas aparecem na lista |
| Limite inferior | Clicar em `−` muitas vezes | Quantidade para em 1 |
| Limite superior | Clicar em `+` muitas vezes | Quantidade para em 10 |
| Mudança de sabores | Trocar o checkbox selecionado | Preço não muda |
| Finalização sem nome | Clicar no botão final | Ação bloqueada na etapa 07 |

**Registro da experiência:** escolha dois casos. Para cada um, escreva: (a) o que você previa; (b) o que ocorreu; (c) que linha ajuda a explicar o comportamento; (d) que melhoria faria.

## Bônus curto: Git no laboratório (fora do playground)

O playground é excelente para investigar **componentes**. Já os comandos Git são executados no terminal do computador do laboratório, dentro da pasta do projeto. Antes de qualquer comando, confirme se a pasta já é um repositório: `git status`. Só use `git init -b main` se ainda não houver um repositório.

```bash
git status
git init -b main
# Nos computadores compartilhados, configure a autoria só neste projeto:
git config --local user.name "Nome da dupla"
git config --local user.email "email@exemplo.com"
git add .
git commit -m "Inicia formulario Pizza Vue"
git log --oneline
```

Ao terminar as missões essenciais, crie o segundo commit com mensagem que conte **o que realmente mudou**, por exemplo `Adiciona quantidade e total reativo`. Para enviar ao GitHub, somente se o remoto e o acesso estiverem previamente configurados, confira `git remote -v` e então use `git push -u origin main` (ajuste o nome da branch se diferente). Nunca compartilhe senha, token ou credenciais na projeção.


## Problemas comuns e como investigar

| Sintoma | Hipótese para testar |
|---|---|
| A interface não atualiza | Foi usado `v-model`? O dado é `ref`? |
| O navegador mostra erro de propriedade | A referência ao objeto selecionado pode estar indefinida |
| O total não muda com a quantidade | O cálculo lê `quantidade.value` dentro de `computed`? |
| Um checkbox apaga a seleção anterior | O estado usado é um array, e cada checkbox tem `:value` distinto? |
| Botão permite quantidade 0 | A regra foi aplicada na função, não só no botão? |
| O botão final fica bloqueado | Nome tem texto diferente de espaços e há pelo menos um sabor? |

## Bilhete de saída — responda sem consultar o código

1. O que faz `ref`, em uma frase e com exemplo da pizzaria?
2. Por que `total` é `computed`, e não um número digitado?
3. Qual diferença entre usar `v-if` e `v-for` neste projeto?
4. Que teste prova que a quantidade respeita os dois limites?
5. Qual decisão sua dupla tomou para tornar a interface mais clara ou justa para o usuário?

## Preparar o projeto local

Git e npm são usados no terminal, fora do playground. Use Node.js compatível com Vite e confirme a preparação com a equipe.

```bash
npm create vite@latest meu-projeto -- --template vue
cd meu-projeto
npm install
npm run dev
```

Substitua `src/App.vue` pelo código inicial da missão atual. Para conferir o resultado de produção, use `npm run build` e `npm run preview`. Os arquivos da missão são o ponto de partida; não é preciso obter o projeto final.

Registre duas etapas com Git quando o laboratório permitir. Não é necessário fazer push nem autenticar uma conta pessoal para concluir a aula.
