## O que você vai construir

Agora vamos **transferir** o que aprendemos na pizzaria para outra situação: organizar tarefas acadêmicas, pessoais ou de trabalho. O desafio essencial é criar, validar, listar e excluir tarefas. Depois, você poderá melhorar a apresentação com Bootstrap, editar itens e descobrir componentes e rotas.

**Entregas observáveis do encontro:** formulário com título e descrição; validação de campos; lista dinâmica com `v-for` e `:key`; confirmação antes de excluir; dois commits locais; apresentação da solução para outra dupla.

> **Limitação importante:** os itens ficam **somente na memória da aplicação**, enquanto a página está aberta. Atualizar o navegador reinicia a lista. Não há banco de dados, login, armazenamento local ou API nesta adaptação.

## A pergunta geradora

Você já precisou lembrar de uma entrega, prova ou reunião? Se uma lista aceita uma tarefa sem conteúdo, apaga itens sem confirmar e não mostra o que foi cadastrado, ela realmente resolve o problema? A resposta não é apenas técnica: envolve necessidades reais, clareza e respeito a quem usa a interface.

### Critérios de aceite negociados

1. A pessoa informa **título** e **descrição**.
2. O formulário rejeita os campos vazios ou compostos só por espaços.
3. Os itens salvos aparecem como cards na tela, sem duplicar o HTML manualmente.
4. Existe uma mensagem quando não há tarefas.
5. Excluir pede confirmação e permite cancelar.
6. O número de tarefas exibido acompanha o array de dados.
7. A edição, data de criação, componentes reutilizáveis e rotas são **aprofundamentos** — não bloqueiam a aprendizagem do núcleo.

## Preparação

Use o playground Vue 3 para as primeiras missões, sempre copiando o código inicial da missão. Os códigos iniciais são progressivos. No laboratório, crie um projeto Vite com o código inicial da missão e explore Bootstrap com o link do CDN no HTML. Alguns assuntos (roteador com múltiplas telas, Git e Vite) precisam do laboratório com arquivos e terminal.

### Uma tarefa é um objeto, uma lista é um array

```js
const tarefa = {
  id: 1,
  titulo: 'Estudar Vue',
  descricao: 'Fazer o desafio de listas'
}
const tarefas = [tarefa]
```

`id` identifica a tarefa, mesmo se duas tarefas tiverem o mesmo título. `titulo` e `descricao` são informações que o usuário preenche. `tarefas` armazena vários objetos. Na aplicação real da unidade, usamos `ref([])` para transformar o array em estado reativo, acompanhado pelo Vue.

### Três perguntas antes de cada mudança

- **Estado:** qual informação precisa estar guardada?
- **Evento:** que ação o usuário fará (digitar, salvar, editar, excluir)?
- **Resultado visível:** o que deve mudar na tela depois dessa ação?


## Bônus Bootstrap: leia, compare, decida

Bootstrap não substitui o Vue e não determina as regras de validação. É uma biblioteca de estilos e componentes visuais. No projeto local há um `<link>` para o CSS do Bootstrap 5. No playground, os estilos básicos próprios mantêm o exemplo legível mesmo sem CDN.

| Classe | Efeito esperado | Onde testar |
|---|---|---|
| `container` | Limita largura e organiza margens | Elemento principal |
| `py-4` | Adiciona espaçamento vertical | Contêiner |
| `card` | Apresenta uma região como cartão | Formulário / lista |
| `form-control` | Padroniza aparência de inputs | Título e descrição |
| `btn btn-primary` | Visual de botão primário | Salvar tarefa |

**Investigação:** se você retirar `form-control`, o cadastro deixa de funcionar? Se retirar `v-model`, apenas o estilo muda ou os dados também deixam de chegar ao estado?



## Git em duas fotografias (somente laboratório)

No primeiro commit, registre a **estrutura base**. No segundo, registre o núcleo funcionando (cadastro, validação, listagem e exclusão). Antes de criar o repositório, use `git status` para verificar se a pasta já é versionada. Em computadores compartilhados, configure usuário e e-mail **localmente** e não exponha credenciais.

```bash
git status
git init -b main
git config --local user.name "Nome da dupla"
git config --local user.email "email@exemplo.com"
git add .
git commit -m "Cria estrutura da lista de tarefas"
# Depois das mudanças essenciais:
git add .
git commit -m "Implementa cadastro, listagem e exclusao"
git log --oneline
```

Se houver remoto autorizado, confira `git remote -v` e a branch antes de usar `git push`. A publicação no Vercel não faz parte da conclusão obrigatória deste encontro.

## Testes de aceite entre duplas

| Caso | Ação | Resultado esperado |
|---|---|---|
| Tudo vazio | Clicar em Adicionar | Mostra erro, não cria item |
| Só título | Informar somente título | Não cria item |
| Título e descrição | Preencher os dois campos | Cria tarefa e limpa formulário |
| Dois títulos iguais | Cadastrar itens diferentes com mesmo título | Dois cards distintos |
| Lista vazia | Abrir app sem tarefas | Mensagem de vazio visível |
| Excluir/cancelar | Pedir exclusão e cancelar | Item permanece |
| Excluir/confirmar | Confirmar exclusão | Apenas item selecionado sai |
| Editar/cancelar | Alterar formulário e cancelar | Item original preservado |
| Editar/salvar | Alterar e salvar edição | Só a tarefa escolhida muda |
| Recarregar página | Atualizar aba | Itens se perdem nesta versão em memória |

**Pergunta para outra dupla:** que comportamento ficou claro? O que causou dúvida? Qual mudança preservaria a autonomia do usuário?

## Depuração: falhas comuns merecem investigação

| Sintoma | O que verificar |
|---|---|
| Digitação não chega ao estado | `v-model` está nos dois campos? |
| A página recarrega ao enviar | Usou `@submit.prevent`? |
| Registros duplicam visualmente de modo estranho | Cada `:key` identifica um `id` único? |
| Excluir remove item errado | O filtro compara `id`, e não título/índice? |
| Cancelar edição ainda altera o card | O formulário está ligado diretamente ao objeto da lista? |
| O contador fica incorreto | Ele vem de `computed(() => tarefas.value.length)`? |
| Bootstrap não aparece | O link CDN carregou? As classes existem no elemento? |

## Bilhete de saída

1. Por que o projeto usa `ref([])` e `v-for` juntos?
2. O que `:key="tarefa.id"` resolve?
3. Como uma função de exclusão pode respeitar a decisão de cancelar?
4. Qual a diferença entre mudar a aparência com Bootstrap e mudar o estado com Vue?
5. O que você conseguiria reutilizar dessa solução em uma lista de livros, inscrições ou eventos?

## Preparar o projeto local

Git e npm são usados no terminal, fora do playground. Use Node.js compatível com Vite e confirme a preparação com a equipe.

```bash
npm create vite@latest meu-projeto -- --template vue
cd meu-projeto
npm install
npm run dev
```

Substitua `src/App.vue` pelo código inicial da missão atual. Para conferir o resultado de produção, use `npm run build` e `npm run preview`. Os arquivos da missão são o ponto de partida; não é preciso obter o projeto final.

Registre duas etapas com Git quando o laboratório permitir. Não é necessário fazer push nem autenticar uma conta pessoal para concluir a aula.
