> **A pergunta que orienta esta unidade:** por que uma interface consegue mudar enquanto digitamos, clicamos ou selecionamos opções, sem precisarmos atualizar a página?

## Como estudar este material

Você não precisa decorar nomes de ferramentas. Precisará compreender **qual problema cada uma resolve**, observar comportamentos, criar hipóteses e testar pequenas mudanças. Este é o começo de um percurso que culmina em dois projetos reais: o formulário de pedidos da **Pizza Vue** e um gerenciador de tarefas (**To-Do List**).

Em cada laboratório você encontrará: **situação-problema → previsão → código inicial → investigação → desafio → reflexão**. É perfeitamente aceitável errar uma hipótese. O objetivo é explicar o que mudou e por quê, não apenas fazer o código funcionar.

**Ao concluir esta unidade, você deverá conseguir:**

1. Explicar as responsabilidades de HTML, CSS, JavaScript e Vue.js, sem confundir estrutura, aparência e comportamento.
2. Diferenciar Node.js, npm, Vite, Git e GitHub e compreender o fluxo básico do desenvolvimento.
3. Reconhecer o papel de Bootstrap, Vue Router e Vercel.
4. Identificar a organização de um componente Vue de arquivo único (`.vue`).
5. Experimentar interpolação, `ref`, `v-model`, eventos, `computed`, `v-if`, `v-for` e `:class`.
6. Formular explicações próprias e adaptar exemplos para situações novas.


## 1. O mapa das tecnologias

As tecnologias foram organizadas em três grupos **didáticos**, não em três graus absolutos de importância. Uma ferramenta pode ser indispensável para executar o projeto sem ser um conceito fundamental do Vue; um complemento pode se tornar essencial em um projeto maior.

| Categoria | Tecnologias | Pergunta-chave |
|---|---|---|
| **Essencial** | HTML5, CSS3, JavaScript, Vue.js 3 | *Do que uma interface é feita e como ela reage?* |
| **Ferramentas** | Node.js, npm, Vite, Git, GitHub | *Como desenvolvemos, executamos e registramos o trabalho?* |
| **Complementar** | Bootstrap, Vue Router, Vercel | *Como organizamos, estilizamos e publicamos a aplicação?* |

### 1.1 Entenda a diferença por meio de uma pizzaria

Imagine uma página em que o cliente escolhe uma pizza. **HTML** descreve o formulário e o botão; **CSS** deixa o pedido legível e agradável; **JavaScript** permite cálculos e decisões; e **Vue.js** conecta os dados da aplicação ao que a pessoa vê. Em vez de escrever instruções manuais para atualizar cada pedaço da página, declaramos como a interface depende do estado.

```text
CLIENTE → digita / clica / seleciona
               ↓
       ESTADO DA APLICAÇÃO (Vue)
               ↓
       INTERFACE ATUALIZADA
```

No projeto Pizza Vue, uma alteração na **quantidade** pode atualizar o **total**; na To-Do List, adicionar uma tarefa pode atualizar a **lista** e a **contagem**. A lógica se parece; o problema da vida real muda.


## 2. Essencial — quatro tecnologias, quatro responsabilidades

### HTML5: estrutura e significado

HTML é a linguagem de marcação que descreve o conteúdo. `<main>` indica a parte principal; `<h1>` apresenta o título; `<label>` identifica um campo; `<button>` representa uma ação. Uma página não precisa de Vue para ter estrutura.

```html
<main>
  <h1>Pizza Vue</h1>
  <label for="sabor">Sabor</label>
  <input id="sabor" placeholder="Digite o sabor">
  <button type="button">Adicionar</button>
</main>
```

**Por que importa?** Um rótulo associado ao campo facilita a compreensão para todas as pessoas, inclusive quem usa tecnologias assistivas. Na To-Do List, o HTML comunica o que é uma tarefa, o que é um botão de exclusão e o que é uma lista.

### CSS3: aparência e organização visual

CSS define a apresentação da estrutura. Regras como `padding`, `color`, `display` e `border` controlam espaçamento, texto e disposição. CSS, sozinho, não cria a lógica de salvar um pedido.

```css
.cartao {
  padding: 1rem;
  border: 2px solid #167b52;
  border-radius: 12px;
}
```

No curso, veremos primeiro CSS simples. Depois, conheceremos o Bootstrap, que fornece um sistema de classes prontas para acelerar parte do trabalho visual.

### JavaScript: dados, decisões e acontecimentos

JavaScript é a linguagem de programação que usamos para representar preços, quantidades, nomes, listas de tarefas e funções de ação. O pequeno cálculo abaixo funciona como JavaScript puro:

```js
const preco = 35
const quantidade = 2
const total = preco * quantidade // 70
```

**Atenção:** uma constante comum não se transforma automaticamente em um estado reativo quando você altera seu valor. O Vue fornece recursos específicos para que as mudanças de estado sejam acompanhadas pela interface.

### Vue.js 3: declarando a interface a partir do estado

Vue.js é um framework JavaScript progressivo para construir interfaces. **Progressivo** significa que ele pode ser adotado de modo gradual; **reativo** significa que mudanças nos dados observados podem desencadear atualizações da interface; **componentizado** significa que a interface pode ser organizada em partes reutilizáveis.

```vue
<script setup>
import { ref } from 'vue'
const nome = ref('Visitante')
</script>

<template>
  <input v-model="nome" />
  <p>Olá, {{ nome }}!</p>
</template>
```

Ao mudar o campo, a mensagem muda. É este fenômeno que você investigará nos exercícios, antes de memorizar o significado de cada diretiva.


## 3. Ferramentas — como o projeto sai da ideia e chega ao navegador

### Node.js não é o mesmo que Vue

Node.js é um ambiente que executa JavaScript fora do navegador. No minicurso, ele é usado principalmente **durante o desenvolvimento**: ferramentas de projeto rodam por meio dele. Isso não significa que a pizzaria terá um servidor backend Node.js.

### npm é o gerenciador de pacotes

O npm ajuda a instalar bibliotecas e executar scripts configurados no projeto. Você verá comandos como:

```bash
node --version
npm --version
npm install
npm run dev
```

`npm install` instala dependências listadas no projeto; `npm run dev` aciona o script de desenvolvimento definido no `package.json`. A presença do comando não diz, sozinha, qual ferramenta executará o servidor: isso é definido no projeto.

### Vite é a ferramenta que organiza a experiência de desenvolvimento

Vite fornece servidor local rápido, atualização durante a edição e um processo de compilação para produção. É muito usado com Vue. Num projeto típico, o navegador abre um endereço de desenvolvimento enquanto você altera os componentes.

```text
Você edita App.vue → Vite serve os arquivos → navegador mostra a mudança
```

### Git registra; GitHub compartilha

**Git** é um sistema de controle de versões instalado no computador. **GitHub** é uma plataforma que hospeda repositórios Git e permite colaboração. Eles se complementam, mas não são a mesma coisa. Um commit funciona como um registro de uma etapa significativa do trabalho.

```bash
git status
git add .
git commit -m "feat: adiciona resumo reativo"
git log --oneline
```

Esses comandos serão executados no **terminal**, e não dentro de um editor de componentes Vue. Nesta unidade, precisamos primeiro entender *qual problema eles resolvem*.

### O caminho completo

```text
VS CODE (edição) → NODE.JS + NPM + VITE (ambiente)
         ↓
      VUE.JS + HTML + CSS + JAVASCRIPT (aplicação)
         ↓
      NAVEGADOR (teste e DevTools)
         ↓
      GIT → GITHUB (histórico e compartilhamento)
         ↓
      VERCEL (versão publicada)
```


## 4. Complementar — quando a aplicação começa a crescer

### Bootstrap: classes para montar a aparência

Bootstrap é um framework CSS. Ele oferece classes de espaçamento, formulários, botões e grade responsiva. A classe `btn btn-success` pode dar estilo a um botão, mas não cria sozinha uma função para cadastrar uma tarefa.

```html
<button class="btn btn-success">Adicionar tarefa</button>
```

**Pergunta:** a classe altera a aparência ou também insere um item na lista? O botão só fará o cadastro quando houver lógica conectada ao evento.

### Vue Router: qual tela deve aparecer?

Vue Router faz o gerenciamento das rotas de uma aplicação Vue. Por exemplo, a rota `/tarefas` pode exibir um componente de listagem, enquanto `/sobre` mostra outra tela. Isso é diferente de mostrar e esconder uma mensagem usando `v-if`. O roteador será aprofundado quando houver necessidade real de navegação.

### Vercel: publicação na web

Vercel é uma plataforma de implantação e hospedagem. O código é desenvolvido localmente, versionado e pode ser publicado para que outras pessoas acessem um endereço web. **Publicar** não é a mesma coisa que **executar** um projeto no playground.

## 6. Antes dos laboratórios — como ler um arquivo `.vue`

Um componente Vue de arquivo único (*Single-File Component*, SFC) pode ter três partes:

```vue
<script setup>
// Lógica e dados JavaScript
</script>

<template>
  <!-- Elementos que serão mostrados -->
</template>

<style scoped>
/* Aparência aplicada ao componente */
</style>
```

- **`<script setup>`:** JavaScript do componente; aqui criamos estado e funções.
- **`<template>`:** descreve a interface, usando HTML e recursos do Vue.
- **`<style scoped>`:** define estilos associados ao componente (com escopo de CSS do SFC).

Dentro de `<script setup>`, acessamos um `ref` usando `.value`; em templates, o Vue geralmente o disponibiliza sem que escrevamos `.value`.

### Como executar os exercícios no playground

1. Abra o playground indicado na wiki e procure um editor de **componentes Vue SFC** (por exemplo, um arquivo `App.vue`).
2. Substitua **somente o conteúdo de `App.vue`** pelo código inicial da missão.
3. Observe o resultado e faça primeiro uma previsão antes de alterar o código.
4. Depois de cada alteração, verifique a prévia e, se houver erro, leia a mensagem do editor.
5. Registre em uma frase o que mudou e por quê. Trabalhe em dupla quando possível.

**Compatibilidade:** o DevLab executa Vue 3 SFC, com um único `App.vue` e imports de `vue`. Componentes em vários arquivos, Router, Git e comandos npm exigem o projeto local no laboratório.

### Um protocolo de pesquisa para cada desafio

**Prever (1 min):** o que você espera ver? **Experimentar (3–5 min):** altere somente o necessário. **Explicar (2 min):** por que o resultado mudou? **Transferir (2 min):** como usar a ideia na To-Do List?

## 7. Desafios de interpretação — sem instalar nada no playground

Algumas tecnologias não são executadas dentro de um único componente Vue. Por isso, investigamos agora sua função e deixamos a execução para o laboratório local.

### Desafio A — Quem faz o quê?

Uma pessoa quer: **(a)** instalar bibliotecas; **(b)** abrir a aplicação em desenvolvimento; **(c)** guardar uma versão do código; **(d)** compartilhar o repositório; **(e)** publicar um site. Associe cada objetivo a **npm, Vite, Git, GitHub e Vercel**. Compare com sua dupla e explique por que não é a mesma ferramenta para todos os casos.

### Desafio B — O que o Bootstrap não faz sozinho?

Um botão recebeu `class="btn btn-success"`. Ele agora tem uma aparência adequada, mas ainda não adiciona tarefas. Escreva uma hipótese sobre o que falta e indique qual tecnologia será responsável por essa lógica.

### Desafio C — Como o projeto se organiza?

Observe as seguintes situações: **a tela muda quando clico**, **mudo da página inicial para a página de tarefas**, **uma pessoa de outra cidade acessa o site**, **quero retornar a uma versão anterior**. Associe respectivamente os recursos mais relevantes: **Vue/JavaScript, Vue Router, Vercel, Git**. Justifique com suas palavras.
